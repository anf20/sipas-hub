	1. Pendahuluan
1.1 Latar Belakang
Pengelolaan keuangan sekolah, khususnya pembayaran SPP dan biaya kegiatan siswa, masih banyak dilakukan secara manual. Proses ini rentan terhadap kesalahan pencatatan, keterlambatan pelaporan, dan kurangnya transparansi bagi orang tua. SIPAS-Hub hadir sebagai solusi digital berbasis web yang memungkinkan administrasi sekolah mengelola tagihan secara otomatis, sementara orang tua dapat memantau dan melakukan pembayaran secara online kapan saja.
1.2 Tujuan Proyek
* Otomatisasi generate tagihan SPP bulanan untuk seluruh siswa aktif
* Transparansi tagihan: orang tua dapat melihat semua tagihan dan riwayat bayar
* Efisiensi administrasi: mengurangi pekerjaan manual staff keuangan
* Fondasi untuk integrasi payment gateway di fase berikutnya
1.3 Ruang Lingkup
* Manajemen data master: siswa, kelas, tahun ajaran, jenis tagihan
* Generate & kelola tagihan SPP bulanan dan tagihan kegiatan
* Portal orang tua untuk lihat tagihan dan riwayat bayar
* Pencatatan pembayaran manual oleh admin
* Laporan & dashboard keuangan
* Integrasi payment gateway (Fase 3 — dikerjakan terakhir)

* students → classes (many-to-one): Satu siswa satu kelas aktif
* students → users (many-to-one via parent_user_id): Satu ortu bisa punya banyak anak
* invoices → students (many-to-one): Satu siswa banyak tagihan

5. Spesifikasi Fitur
5.1 Autentikasi & Manajemen Pengguna
* Login multi-role dengan email + password
* Role-Based Access Control: admin tidak bisa akses portal ortu, dan sebaliknya
* Reset password via email
* Admin dapat buat, edit, dan nonaktifkan akun user
* Saat akun ortu dibuat, sistem kirim email berisi kredensial login otomatis
5.2 ★ Modul Data Siswa [PRIORITAS 1]
Modul ini adalah fondasi seluruh sistem dan harus selesai lebih dulu.
CRUD Data Siswa
* Form registrasi siswa dengan validasi lengkap
* NIS (auto-generate jika dikosongkan, format YYXXXX)
* Data pribadi: nama, tempat/tanggal lahir, jenis kelamin, agama, alamat
* Data keluarga: nama ayah/ibu/wali, pekerjaan, nomor HP wali
* Data akademik: Kelas (wajib), tahun masuk, status (aktif/lulus/keluar/pindah)
* Alur Pendaftaran: Admin wajib menginput Kelas di awal pendaftaran (Strict Consistency)
* Upload foto siswa (resize otomatis)
* Edit data siswa dengan validasi
* Soft delete siswa (nonaktif), bukan hapus permanen
* Kenaikan kelas: wizard pindah siswa ke kelas baru (akhir tahun ajaran)
* Import siswa massal via Excel/CSV dengan template yang bisa diunduh
* Export daftar siswa ke Excel & PDF
* Filter & pencarian: by NIS, nama, kelas, status
Manajemen Kelas
* CRUD kelas per tahun ajaran dengan kapasitas
* Assign wali kelas ke kelas
* Pindah siswa antar kelas
* Daftar siswa per kelas (roster) dengan foto
Manajemen Akun Orang Tua
* Admin create akun ortu + link ke satu atau lebih data siswa
* Satu akun ortu dapat di-link ke beberapa siswa (kakak-adik)
5.3 ★ Modul Tagihan [PRIORITAS 1]
Modul inti kedua, harus selesai setelah modul siswa siap.
Master Jenis Tagihan
* CRUD jenis tagihan: nama, kategori (SPP/kegiatan/seragam/lain), nominal default
* Konfigurasi recurring: bulanan / tahunan / sekali
* Setting berlaku untuk jenjang/kelas tertentu atau semua
* Histori perubahan nominal
Generate Tagihan SPP Bulanan
* Admin pilih: bulan, tahun, jenis tagihan SPP
* Filter scope: semua siswa aktif / per jenjang / per kelas tertentu
* Preview daftar siswa + nominal sebelum dieksekusi (konfirmasi wajib)
* Preview menampilkan status: 'Akan dibuat' vs 'Sudah ada (skip)'
* Eksekusi via Laravel Job di background queue + progress indicator
* Sistem cek duplikasi: tidak buat ulang jika tagihan bulan tersebut sudah ada
* Laporan hasil: jumlah berhasil, jumlah skip (duplikat), jumlah gagal
* Log: generate dicatat siapa, kapan, berapa siswa, bulan berapa
Generate Tagihan Kegiatan
* Admin buat event kegiatan dengan nominal biaya
* Pilih peserta: semua siswa aktif / per kelas / pilih manual
* Generate tagihan ke peserta terpilih
* Tracking status konfirmasi keikutsertaan per siswa
Kelola Tagihan Individual
* Tambah tagihan manual per siswa (di luar SPP & kegiatan)
* Edit nominal tagihan dengan input justifikasi
* Batalkan tagihan (void) dengan log alasan
* Perpanjang tanggal jatuh tempo
5.4 Pembayaran Manual (Admin)
* Admin cari siswa lalu pilih tagihan yang akan dibayar
* Input: nominal bayar, metode (tunai/transfer/dll), tanggal, bukti (foto/scan)
* Sistem validasi nominal dan update status invoice otomatis
* Generate nomor kwitansi otomatis (format: SCH-YYYYMM-XXXXXX)
* Cetak / download kwitansi PDF
* Notifikasi ke ortu saat pembayaran direkam
5.5 Portal Orang Tua
* Dashboard: ringkasan tagihan, informasi anak, visualisasi metrik dengan UI mobile-first.
* Daftar tagihan: filter by anak, by status, desain badge dinamis.
* Detail tagihan: rincian biaya, periode, instruksi bayar, tombol "Bayar Sekarang" terintegrasi Midtrans Snap JS.
* Riwayat pembayaran: semua transaksi dengan fitur download kwitansi resmi (PDF).
* Pengaturan Akun: halaman khusus portal orang tua untuk ubah profil dan keamanan.
* Profil anak: data akademik, kelas, wali kelas, foto.
5.6 Dashboard & Laporan Admin
* Summary cards: Pemasukan Bulan Ini, Total Tunggakan, Rate Penagihan (UI unifikasi berbasis metrik warna).
* Visualisasi Keuangan: Progress bar pelunasan SPP & Tagihan Lainnya, dilengkapi data agregat jumlah siswa yang terbebani vs lunas.
* Tabel tagihan jatuh tempo & riwayat aktivitas keuangan.
* Laporan rekap: Export transaksi ke format PDF menggunakan DomPDF.
5.7 Integritas Data & Keamanan Sistem (Nilai Tambah Implementasi)
* Automated Audit Trail: Menggunakan Eloquent Traits untuk merekam setiap aksi (Create/Update/Delete) pada transaksi, menyimpan old_values & new_values beserta IP Address pengguna.
* Transaction Locking Logic: Penguncian atribut krusial (Nominal & Kategori) secara otomatis pada model Tagihan (Invoice) jika telah memiliki minimal satu transaksi pelunasan, mencegah anomali akuntansi.
* Robust Webhook Security (Midtrans Callback):
- Anti-Timing Attack: Menggunakan `hash_equals()` untuk komparasi signature key.
- Pessimistic Locking: Menggunakan `lockForUpdate()` dalam Database Transaction untuk mencegah Race Condition saat menerima concurrent callbacks.
- Parameter Tampering Protection: Validasi strict antara `gross_amount` dari gateway dengan `amount` di database lokal.6. User Stories

11. Log Progres & Pencapaian (Changelog)
----------------------------------------
[Kamis, 4 Juni 2026]
Fitur & Optimasi yang Telah Diselesaikan:
1. Keamanan Data (Soft Delete): Implementasi soft delete pada data keuangan (Invoice & Payment) untuk menjaga integritas audit historis.
2. Pusat Pemulihan Data (Recovery Center): Antarmuka khusus Super Admin untuk me-restore atau menghapus permanen data yang telah di-soft-delete (Siswa, Tagihan, Pembayaran).
3. Pembayaran Massal (Bulk Payment): Orang tua kini dapat memilih dan membayar beberapa tagihan sekaligus dalam satu transaksi Midtrans.
4. Biaya Layanan Dinamis (Customer Absorb): Penyesuaian fee otomatis berdasarkan metode yang dipilih (Flat Rp4.500 untuk VA, 0.7% untuk QRIS, 1.5% untuk Dana).
5. Pembatasan Metode Pembayaran: Mengunci opsi Midtrans hanya pada QRIS, VA BCA, VA BRI, VA Mandiri, dan Dana.
6. Pusat Bantuan (Q&A): Penambahan halaman bantuan interaktif (Alpine.js) di Portal Orang Tua dengan tautan global di footer.
7. Konsistensi UI/UX: Sinkronisasi rona background, font (Lexend & Inter), dan ikon (Flux UI SVG) di seluruh portal orang tua dan halaman login.
8. Keputusan Teknis Autentikasi: Menonaktifkan kewajiban verifikasi email (MustVerifyEmail) untuk mempermudah login orang tua, karena pembuatan akun bersifat tersentralisasi.

Persiapan Deployment VPS (Terjadwal: Besok Malam):
- Target Server: VPS (min 2GB RAM), Ubuntu 22.04 / 24.04.
- Control Panel: CloudPanel (Gratis & Mudah digunakan).
- Tahapan Utama: Pull branch dari GitHub, Instalasi dependensi (PHP 8.4 & Node.js/Vite), Konfigurasi .env (Database & SMTP), dan penyesuaian Webhook Midtrans (Production URL).
